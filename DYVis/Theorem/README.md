# DYVis.Theorem — theorem diagrams

Draws what a DyLean security theorem permits, **generated from the Lean
statement**. Reference theorems live in `Example.lean` (proofs are `sorry` — the
shape of the statement is the subject, not its truth).

## Using it on your own theorems

Import the extractor and trace theorems where they are proved; nothing has to
be listed centrally.

```lean
import DYVis.Theorem.Extract

-- the module prefixes whose declarations count as your model
set_option dyvis.model "MyProtocols DY DYVis"

theorem my_guarantee … := by …
#traceClaim MyProtocols.my_guarantee

-- at the foot of the module, for everything traced above
#traceClaimsToFile "diagrams/claims/myproto.json"
```

Paths are relative to the root of the package the module is in, and
intermediate directories are created. `#traceClaimsToFile` clears
the buffer, so several modules can each write their own file.

**Write into one data directory's `claims/`.** A data directory holds
`claims/`, `accepted/` (approved snapshots) and `current/` (latest snapshots,
not committed); the approval tests and the viewer's source picker enumerate it.
The tools read it from `DYVIS_DATA`, defaulting to this package's own
`diagrams/` (see `viewer/tests/data.mjs`).

Then start the review server and open the page:

```
lake build <your module>                      # elaborating it IS the extraction
DYVIS_DATA=<workspace>/diagrams scripts/review.sh   # serves on 8730, and can accept
# http://127.0.0.1:8730/viewer.html?claims=claims/myproto.json
```

The accept control, the source picker and the jump to code all need the review
server, and stay out of the way without it. Any static server over `viewer/`
still draws a claims file loaded with **open**.

With no `?claims=`, the page reads `claims/reference.json` (the reference
theorems, regenerated by `lake build` in this package), or the first claims
file of the data directory if there is none.

Under the review server a dropdown lists every claims file; served any other
way, **open** loads one from disk. The bar shows which file is being drawn, and
says so if it cannot be loaded.

## Reviewing the diagrams

The diagrams are covered by APPROVAL tests, not assertions: what is recorded is
the picture itself, and a diff means one changed and wants looking at -- not
that anything is wrong. You decide.

```
scripts/snapshot.sh                 # what changed
scripts/snapshot.sh --check         # fail ONLY on approved diagrams that
                                    # changed -- usable as a gate while
                                    # the baseline is incomplete
scripts/snapshot.sh --accept a b    # accept from the terminal
scripts/review.sh                   # accept from the picture
```

In the viewer, `●` marks a changed diagram and `○` a new one; **accept** records
the one on screen and moves to the next undecided. `a` accepts, `j` skips, `u`
unfolds. The counter at bottom right is what is left. **args** switches event
labels between full arguments and an abbreviation.

**Accepting is a person's decision.** The baseline says a human looked at the
picture and agreed it says what the theorem says — that is the whole content of
the test, and it is the only part of this pipeline not checked by the pipeline
itself. An agent that accepts its own output records a review that did not
happen, and does it in the one place where nothing else would notice. See
`AGENTS.md`.

## Where an event is emitted

An event box carries a glass; clicking it lists the declarations that can log
that event, and clicking one of those opens it in the editor.

The list is the reachable model's OWN emitters. `Extract.lean` takes the config
from the theorem's own `Trace.Reachable` premise -- so it is whatever THAT
theorem quantifies over, and emitters of protocols it says nothing about are
excluded. It over-approximates: a branch a guard never takes still counts. That
is the safe direction, since a site shown can be checked and dismissed, whereas
a site missing would say there are none.

A claim names a declaration, never a line: a line recorded at extraction time is
one the source can move out from under. The review server resolves the name
against the file as it is now, and opens it with `code --goto` -- from the
machine the files are on, rather than by handing the browser a `vscode://` URI,
which fails silently when the browser is on the other side of a remote boundary
from the editor. A host that needs a different URI for the fallback link names
it in `DYVIS2_EDITOR_URI`, with `{path}` and `{line}`.

What gets stored is a rendering of `elements()` -- the last point at which the
drawing is data, after the `⟦n⟧` numbering, edge marks and containment, before
layout. So a change in `graph.js` shows up as well as one in `lower.js`.
Baselines live in the data directory's `accepted/`, one file per diagram, holding both the
folded and unfolded view.

A rendering, though, and **what it leaves out it cannot gate**. That was
measured rather than assumed. Reversing the palette used to leave every baseline
byte-identical; and the parallel copies of one step that the choice-box defect
produced were recorded as *repeated identical lines*, with nothing to say they
differed in colour — the record showed there were now two arrows and not why.
Each edge now carries two further fields, and they are **not** the same fact:
`walk ⟦n⟧` says which walk the step is on, named by the absence that declares
it, while the bare number before it says what is forbidden on that step; and the
hue is a third thing again, since absences that never meet share a colour.
Deliberately still outside the record: geometry, which belongs to `viewer.html`
and carries no meaning, and the abbreviated labels behind **args**, which are
one graph under a display switch.

Only **2 of the 22** reference diagrams have a coloured arrow at all. The colour
machinery is exercised almost entirely by the DANE corpus, which is why a defect
in it went a long way before anything said so.

## Where to look first

**The trace sites.** `#traceClaim thm` emits two declarations beside the theorem:
`thm.claim`, the shape it proposes, and `thm.isClaim`, a proof that the theorem
IS that shape. The proof is `Iff.rfl`, so the claim is not merely equivalent to
the theorem but the *same proposition* — there is no room for the translation to
have quietly changed the meaning.

Each trace in `Example.lean` is followed by its `#print axioms`, so the first
check is **no `sorryAx` in any of them**.

But certification is *faithfulness, not understanding*. `denote (opaque p) tr` is
`p`, so a part of the statement the translation could not classify still
certifies — truthfully, while saying nothing. The second number to read is the
**`opaque` count**, warned at the trace site and recorded per claim in the JSON;
a claim is only informative when it is zero. `accepted_or_attacker_knows` is the
worked control: its escape is a knowledge fact rather than an event, so it
certifies *and* warns, the viewer draws the part it could not read as `? …` and
refuses the diagram.

A theorem that is not about traces at all is **refused** rather than given a
shape — there is no trace, so `stmt ↔ claim.denote tr` cannot be stated. That
refusal is pinned by `#guard_msgs` on `not_a_trace_property`, so this file stops
building if the extractor ever silently accepts one.

**The read-back.** `read.js` reads a laid-out diagram into a claim by the rule a
person is told to use, and compares it with the theorem's. The viewer runs it on
every diagram it shows and banners a disagreement; the snapshot records it as
*reads back as its claim*. It is only worth anything because it is written from
the notation rather than from `lower.js` — mirroring the lowering would share
every misconception and succeed on a picture that misleads every reader.

It reads a number as banning **its own step**, which is all the notation says a
number does, and calls an absence whole-run only where the number is on *every*
step of the run. That is not a refinement: without it a `∄` that stopped at a
merge and one carried to the bar were the same atom, and the check was blind to
the difference for as long as it existed. See the first entry under Known gaps.

**The notation audit.** `auditElements` in `graph.js` checks the picture against
the rules of the notation rather than against the theorem, because the two catch
different things. The read-back is blind by construction to ink that says
nothing: a walk no reader can enter contributes nothing to the claim it
recovers, and duplicate alternatives collapse in the normal form. So the audit
looks for exactly that — a forbidden shape nobody cites, a member of a
conjunction a colour cannot be followed through, **an arrow on no enterable
walk** (grey ones too, which are the easier to overlook), **a colour starting
where it forbids nothing**, and **two dashed boxes bearing one name that do not
hold the same thing**. The viewer banners these too; the snapshot records them
under *does not match the theorem*. All of the last three arrived as real
defects, from three different causes: the fill pass being applied to boxes
holding a *choice*, `distribute` splitting a name and letting both halves keep
it, and an unbounded `∄` not reaching the conjuncts beside the one that declares
it.

## Pipeline

```
Example.lean  --Extract.lean-->  claims.json  --lower.js-->  graph  --> picture
              translate+rewrite                 lay out       |
                                                    read.js <-+  and compare
```

| stage | artifact | can it be wrong about? |
|---|---|---|
| statement → claim | `Extract.lean` | the mathematics — **not yet certified**, see below |
| claim → claim | `Extract.lean` | the mathematics — each rewrite has a proof in `Claim.lean` |
| claim → picture | `lower.js` | only the notation |
| picture → claim | `read.js` | nothing it is trusted for — it is the check on the row above |

`Claim.lean` is the grammar in the middle, with a `denote` written so that
"this claim means exactly this conclusion" is discharged by `Iff.rfl`. Those
certificates are generated, not transcribed.

The rewrites live beside their proofs rather than in the renderer, because each
carries side conditions — an absence must not be narrowed, a bound needs a lone
event premise — and in Lean those are hypotheses that cannot be forgotten. They
were in JS once, where one of them *was* forgotten and the picture asserted an
order the statement does not give.

What remains in `lower.js` is layout: placing events by index, boxing conjuncts,
hanging absences on edges. That can produce an ugly or misleading *picture*, and
no Lean lemma could check it — "converging arrows mean alternatives" is a
convention, not a proposition. What checks it is `read.js`, which is that
convention written out as `readGraph : Graph → Claim` and applied to the drawing.
In JS, so it is evidence rather than proof; doing it in Lean, over a `Graph`
type, is the endgame and a separate project. `distribute` is also still here: it
recurses on a rebuilt term, so moving it needs a termination measure.

## What the extractor recognises

`∨`, `∧`, `¬`, `→`, `∃`, `EventLogged` (whole trace or `tr.prefix i`),
`EventLoggedAt`, bounded absence (`∀ k, j < k → k < i → ¬ ev@k`), any named
predicate (unfolded, keeping the name), and any non-recursive `inductive`
predicate (see below). A `Prop` that does **not** mention `tr` is a *check*; one
that does and is not recognised becomes `opaque`, which renders as a hole and
trips the banner — giving up is never silent. `Example.lean` traces
twenty-two theorems: eleven numbered reference shapes, then nine MVEs added as
real statements turned up shapes they did not cover (two event alphabets in one
statement, value premises beside an event premise, a check projecting a field of
its witness, alternative conditions on one event, a conjunction and a
disjunction behind a name, a trigger with no position, an inductive predicate).
All twenty classify with zero `opaque`; the other two —
`accepted_or_attacker_knows` and `accepted_reached_from_root` — exist to show
what one looks like when they do not, for the two different reasons that happens.

**An `inductive` predicate is a name with no body to unfold.** `unfoldDefinition?`
does not fire on one, so every chain and break predicate in the corpus used to
be an opaque leaf — and, since an opaque leaf is drawn as a *check*, the picture
said a stretch of run was a constraint on values. Where the inductive is not
recursive, its constructor characterisation is a disjunction of existentials
that this grammar already has. What is missing is only the TIE, and that tie is
not definitional — so it is **proved**: `Extract.lean` states `∀ args, I args ↔
⋁ᵢ ∃ fields, indices = args ∧ premises`, discharges it, and adds it to
the environment, where the kernel checks it. The rebuild direction is *emitted*
from the same walk that builds the arms, not searched for: it was a `grind`
once, and that made whether a predicate could be drawn depend on the ambient
environment rather than on the predicate — the same `ChainAuthExec`, copied
verbatim, tied in DANE and not in aDNS because aDNS's trace is a
seventeen-source `#combine` instead of a twelve-source one. The claim carries
the theorem's
name in its `tie` field and the trace site names it, because `isClaim` does not
reach it and it is the one part of a drawing that wants an axiom check of its
own. A predicate whose proof does not go through stays `opaque`; there is no
`sorry` route in, so the failure mode is a hole and never a false picture. The
drawn body is read back OFF the theorem rather than rebuilt, so the shape in the
picture and the shape the kernel checked are one object. `Claim.cases` holds the
predicate itself, so `denote` still reads it and the certificate stays `Iff.rfl`
— that is the difference from `named`, whose body IS the predicate. Each
alternative is wrapped in the constructor it came from, so the box says which
branch a reader is on. `accepted_or_escaped` is the control, and
`Escaped.dyvisCases` beside it is what a generated tie looks like.

A theorem becomes **one** claim: its premises implying its conclusion.
`Reachable` is dropped as ambient — a trace that is not reachable is not a run.

Two rules do the real work:

- **Happens-before is read off indices.** `occursAt ev i` binds `i`; a sibling
  whose region is `before i` becomes its *child* rather than its sibling. That
  is what turns a conjunction into a chain, rather than guessing from the order
  the conjuncts were written in.
- **Binder names are freshened per path.** A name means one value along a path,
  so two witnesses meeting in a conjunction are renamed apart (`offers` /
  `offers'`) while alternatives may reuse the name freely.

## Five rewrites, each proved in `Claim.lean`

The picture is not the statement's syntax tree; five classical rewrites stand
between them. Each is a theorem, not an assumption, so the step is checked:

| rewrite | lemma | why |
|---|---|---|
| `a → b` ⇝ `¬a ∨ (a ∧ b)` | `denote_imp` | both branches become complete runs. Plain `¬a ∨ b` would draw a branch that never says whether `a` happened |
| `¬(a ∧ b)` ⇝ `¬a ∨ ¬b` | `denote_not_and` | each branch is then a single absence, which is drawable |
| `a ∧ (b ∨ c)` ⇝ `(a∧b) ∨ (a∧c)` | `denote_and_or` | a solid box means "all of these", so an alternative left inside one reads as a requirement |
| `a ∧ ∃x. b` ⇝ `∃x. (a ∧ b)` | `denote_and_ex`, `denote_ex_and` | `∃` is a binder, not structure. Left in place it stops the conjunction flattening, and the events under it cannot be placed against the ones beside them |
| whole run ⇝ bounded by the trigger | `denote_bound`, `conclusion_bounded_by_trigger` | the theorem holds of every reachable trace, so it holds of the run truncated just after the trigger — whatever it says exists, exists by then |
| `¬¬ a` ⇝ `a` | `denote_not_not` | a premise is drawn negated in the branch where it fails, so a premise that is ITSELF an absence arrives doubly negated — and a forbidden shape whose body is another one has nothing to show |

The fourth is *not* applied under a `¬` (`¬∃` is not `∃¬`) nor out of a named box,
which is a unit of its own.

The fifth rests on `Trace.Reachable.exists_prefix_containing` (added to `DY/`):
every position of a reachable trace lies in a reachable truncation, because
`Traceful` carries `trIn ≤ trOut` in its type and so a step can only extend the
run. Three restrictions:

- skipped for any branch containing a `∄`, where narrowing would discard exactly
  what the absence asserts;
- skipped unless the branch has **exactly one** event premise. Every premise has
  to survive the cut, so the bound is the *last* of them — and with two premises
  the statement usually does not say which that is (`accepted_after_unrevoked_send`
  gives `accepted@i` and `sent@j` in no order);
- and skipped unless every branch left ALONE is refuted by the truncation. The
  lemma bounds the whole claim against one `n`, so a disjunction cannot have
  some branches narrowed and others not: the branch that holds at the prefix and
  the branch that holds at the full run may be different ones, and then neither
  *drawn* branch follows. What rules a branch out is the trigger — `¬(the
  premise the bound is taken against)` is false on a prefix containing it. So a
  branch left alone has to be exactly that. The first restriction used to imply
  this by accident, being blunt enough to skip anything with a `¬` in it; two
  `#guard_msgs` probes beside `rescope` pin the difference, since no theorem in
  the corpus produces the shape that separates them.

The first is why every diagram has a branch in which the theorem's premises
never come about: **vacuity is drawn, not hidden.**

The first restriction is blunter than the mathematics needs — a `∄` cannot be
narrowed, but the *positive* positions beside it could be, which would turn many
a stacked conjunct into an ordered chain. Measured before building it: of the 56
whole-run occurrences in the corpus that a per-position bound could narrow,
**one** would actually gain, and that one is blocked by the two-premise rule
anyway. The mixed bound — positives read on the prefix, negatives on the full
run — is compositional at `∧` but not at `∨` or `∃`, where the two readings may
be witnessed by different branches or different witnesses. Every DANE conclusion
is a choice of attack explanations of which at least one is an absence and the
rest are occurrences, which is exactly the case it cannot handle: 39 blocked by
a mixed `∨`, 16 by a mixed `∃`. Not worth building.

The third is applied only when it is *needed* — alternatives can usually just
converge on one event, which is far more compact. Two things force it instead:

- **No single event to converge on.** With two event premises there is no
  honest choice of anchor (`accepted_after_unrevoked_send`).
- **A branch carrying an unbounded `∄`.** That absence governs the whole run, so
  it is drawn on every edge of its branch. If the branch merges with a sibling
  before the end of the trace, the mark lands on the sibling's edges too. This
  was not hypothetical: the page used to read `sent → accepted → end` with the
  last edge labelled `∄ sent` (`accepted_was_sent_or_forged`,
  `accepted_offered_or_unoffered`).

Sharing is sound exactly when both branches impose the same constraints on the
shared part; note this has nothing to do with whether the branches are disjoint,
which is neither claimed nor needed.

`distribute` also descends through `∃`, one copy of the witness per alternative.
It is sound (`∃ x, (A ∨ B)` is `(∃ x, A) ∨ (∃ x, B)`), and without it an `∨`
under a witness never reaches an `∧` to distribute against — which is where DANE
buries its choices. It is still not applied under a `¬`.

It does **not** descend through `named`. Splitting a name is sound as a
proposition — `denote (named n c)` is `denote c` — but each copy goes on wearing
the name while holding a fraction of what the name means, and two boxes then
read as the same Lean expression while saying different things. That is what
`peer_proof_of_possession_reachable` used to do: four boxes reading
`ZoneKeyCompromised key`, which is `KSK ∨ ZSK`, holding one arm each, with the
difference visible only after unfolding both to the bottom. The reason to split,
that an alternative inside a box reads as a requirement, is a reason about the
**solid** box; a name draws a bar for its alternatives to converge on, which
says "this is needed, and for it you may take any one of these back". Keeping
that one name whole took the diagram from 463 recorded lines to 214, and from
635 claim nodes — the only one in the corpus over the 400 mark — to under it.

## Notation settled so far

- Time runs **down**; an arrow means *happens before*.
- The run ends at a **horizontal bar** at the bottom. Everything drawn happens
  before it, so it is the anchor rather than any particular event — which is
  what makes a branch in which *nothing* happens still a path on the page: a
  start dot straight to the bar, with `∄ X` on that one edge.
- Reading rule: **start at any box, follow the arrows down, and you have an
  accepted run.** Converging arrows are therefore alternatives and need no
  annotation. The dual matters as much: several *requirements* may not converge
  on one event, so they are boxed together first.
- Alternatives are a **union, not a disjoint union**. Nothing claims they are
  exclusive, and one trace may match several branches.
- **Locality.** Every constraint on a stretch is drawn *at* that stretch, so any
  edge can be read on its own and an unannotated arrow really does mean "anything
  could have happened here". This is what makes "start at *any* box" true, and it
  is why an unbounded `∄` repeats on every edge it governs rather than being
  stated once somewhere above them.
- **Solid container** = conjunction. **Dashed container** = a named predicate
  from the source, foldable on its own. Solid is structure we inferred, dashed
  is a name that exists in the Lean.
- **A name is never split.** Two dashed boxes bearing the same name and the same
  arguments are the same Lean expression, and a reader is entitled to treat them
  so — which means a box may not hold a fraction of what its name means. A name
  whose contents are a choice draws the choice, with a bar to converge on.
- **A conjunct box stacks its members.** Side by side they read as the row of
  alternatives that converging arrows mean everywhere else, which is the one
  thing a solid box must not say. Stacking is not an ordering claim -- there is
  no arrow -- but a box may also hold a chain, and those arrows still order it,
  downwards like every other.
- **Checks** ride on the event that binds their variables. When nothing binds
  them at that level they become their own leaf box. A container never carries
  checks itself, so its contents are always nodes. A placed check NAMES its
  host's witnesses and the leftovers are retried against it, because a witness
  may reach the run only through a condition -- `dnskey'` is named by
  `contains (serialize dnskey') …` and never by `rrsetSigned signer' rrsig'
  rrset'` itself, so `dnskey'.publicKey = key` has nothing to match on the
  first pass and used to float in a box of its own.
- **Alternative conditions on one event** are a **divided cell** on that event,
  not two branches: one event qualifying two ways is one run, not two. A divider
  rather than a box per side, since boxes already mean conjunction here. The
  cell is framed, so its extent is visible — which conditions are inside the
  choice and which are plain requirements beside it. Round the WHOLE cell, never
  round either half, so the frame says where the choice stops without saying
  anything about its sides.
- **Event names keep their type** (`ExampleEvent.accepted`), because the
  constructor alone does not say which event it is. The module path is dropped.
  Named predicates keep only their own name — they are definitions, not
  constructors, so there is nothing to confuse them with.
- **An inductive predicate's alternatives wear their constructors**
  (`KeyBroken.unregistered`). The arms of a `def`'s `∨` genuinely have no names,
  but these do, and they are the author's own words for what each branch means
  — `unregistered`'s doc comment says in as many words that it *is not a
  compromise at all*, which a reader would otherwise have to recover from the
  shape. Qualified by the predicate for the same reason an event is qualified by
  its type: two inductives may well both have a `here`, and the audit reads one
  name as one thing.
- **Absence** (`∄`) rides on edges, never a node — nothing in it happened. The
  forbidden shape is an ordinary sub-graph, drawn unconnected and red, and it
  appears only once a visible edge names it. It is parked in a column below the
  bar: attached to nothing, it would otherwise be laid out *between* real
  branches and push them apart.
- **An event with nothing above it gets a start dot when a ban is in force
  there.** The dot is what carries the ban over the stretch *before* the event,
  and without it a reader may take "nothing drawn above X" for "anything at all
  may have happened before X" — which is precisely what a whole-run `∄` denies.
  Where the event has arrows of its own the dot speaks for the walks those
  arrows are on, and only the WALK's numbers travel back past it: a bounded `∄`
  between two drawn points says nothing about what came before. An event with no
  arrows at all — a member of a conjunction, which the trigger and most leaves
  of a nested one are — is on exactly the runs the enclosing box leaves under,
  so the dot takes the walks of the box's OWN arrows, climbing while the box has
  no arrows either. The climb stops at a CHOICE, which is met one alternative at
  a time and whose members are therefore on a subset of its runs. Where no run
  carries a number the dot is left off, since then it says only "something or
  nothing came before", which is what a reader infers from its absence. Colour
  alone does not earn a dot.
- **Colour is a WALK** — a commitment a reader carries *along a path* rather
  than reads off one step, which is what the reading rule above is about. That
  is the whole of what it is: a path identity, not an absence. The only thing
  that declares a walk today is a `∄` governing a whole path, because that is so
  far the only constraint that has to be carried forward — which is why walks
  are *named* `⟦n⟧` after one. A naming convenience, not the meaning: a future
  constraint that had to be carried along a path would declare a walk too, and
  none of the machinery would need to know it was not an absence. An absence
  that governs a single step — one between two named points — wears its number
  on a plain arrow, because there is no path to carry a colour along and a
  coloured one would invite the reader to keep it. Half the marked arrows in the
  corpus are of each kind. The hue is a third thing again: shared out between
  walks that never meet, so it is not even a unique name for one.
- **A walk is named by its whole CONTEXT.** The set of whole-run absences in
  force on a path, not each of them separately. Named per absence instead, a
  branch under both `∄X` and `∄Y` drew one arrow per member on every step it
  touched, in the colours of the runs beside it — and neither colour then said
  which run the reader was on, because being on `∄X` is not being on the run
  where `∄X` and `∄Y` both hold, and the continuations open to the two are not
  the same. Three consequences, one bullet each below: a conjunction is one
  walk, nested contexts do not swallow each other, and a context needs no member
  the others lack.
- **Two walks a reader cannot be on separately are ONE walk.** A walk is a class
  of runs, so if every step offers both under the same bans, choosing between
  them walks the same nodes forbidding the same things — a commitment with
  nothing on the other side of it. A CONJUNCTION of whole-run `∄`s is that
  shape: `accepted_neither_offered` is one context `{⟦2⟧, ⟦3⟧}` and therefore
  one walk, wearing both numbers, which is what says both hold. It has to stay
  distinct from an ALTERNATIVE over the same stretch, where `∄X` and `∄Y` on one
  arrow would read "neither" against a theorem saying "one or the other" —
  `accepted_one_or_other_unoffered` is that shape, and it is two contexts and so
  two walks.
- **Nested contexts do not swallow each other.** Where `{⟦3⟧}` and `{⟦2⟧, ⟦3⟧}`
  reach the same step, the larger is one walk in a colour of its own, not a
  `⟦3⟧`-coloured arrow beside the `{⟦3⟧}` one banning strictly more.
  `accepted_unoffered_one_or_both` is the smallest case; the DANE and DNS
  headlines had between 2 and 12 each, and it was what every diagram failing its
  read-back for a reason other than an opaque leaf had in common.
- **A context needs no member the others lack.** Dropping the redundant copy by
  drawing a context only under what distinguishes it would leave `{⟦2⟧, ⟦3⟧}`
  beside `{⟦2⟧}` and `{⟦3⟧}` with nothing to be drawn under, and an alternative
  would leave the page — worse than the redundancy, since too few runs refuses
  ones the theorem allows. Naming by the context has no such gap.
  `accepted_unoffered_either_or_both` pins it; nothing in the corpus has the
  shape yet.
- **A colour has to be enterable, and has to be worth entering.** Picking a run  means picking an arrow into the bar *and* a colour, so a coloured arrow no
  arrow of that colour reaches is ink a reader can never be on — either a stray
  copy, or the sign that the arrow which should have led in went missing. And a
  grey walk may take up a colour only where that colour forbids something from
  there on: a colour starting on an unconstrained step asks for a commitment
  with no consequence, and the alternatives it offers cannot be told apart.
- **A bounded `∄` rests at a point in the run**, which an event and the end of  the trace are, and a `def` is not. Unfolding a name shows what is INSIDE it,
  so its arrow abbreviates a region and a mark passes through to that arrow;
  unfolding an event shows what came BEFORE it, which is no business of the step
  leaving it. So folding an event does not push its marks forward onto the step
  after — and where that leaves the stretch off the page entirely, nothing is
  drawn and the `+N` is what says there is more here to look at. The upshot is
  a property worth keeping: **where a bounded `∄` rests does not depend on what
  is folded.**
- **A folded arrow is split per alternative.** A folded node speaks for every
  alternative behind it at once, and they need not be under the same bans;
  unfolded each has its own arrow, so folded they must still be told apart. One
  arrow stamped with the union would assert one alternative's `∄` over the run
  beside it and refuse a run the theorem allows. The bans and the path-contexts
  are paired per alternative rather than multiplied, since the product offers
  combinations no alternative has.
- An edge **names a forbidden shape by number**, `∄ ⟦1⟧`, and the shape itself
  wears that number, `⟦1⟧`. Only the edge carries the `∄` — on both it reads as a
  double negative. Numbers are assigned over the whole graph, so folding cannot
  renumber them, and one edge can carry several. Two edges citing the same
  number are visibly *one* constraint — spelling the name out on each had been
  readable as several. (`⟦n⟧` is the repo's marker convention, cf. DYVis Mermaid
  step indices.)
- **Argument names carry value identity along a PATH.** Disjuncts are separate
  paths, so a name may be reused across them; two witnesses meeting on one path
  must be renamed apart (`offers` vs `offers.1`).
- A **dashed arrow** means *before, or in the same step as*. It is what a
  whole-run claim becomes once bounded by the trigger: the bound is a step
  boundary, not the trigger's index, because one step may log several events
  (`TLS.Client.finished` logs two). A box has one outgoing arrow, so a box
  holding any step-bounded member is drawn dashed as a whole.
- Blue `+N` = how many nodes unfolding reveals.
- **Folding reflows only what that node reveals.** Everything else keeps the
  position it had, so reading one branch does not rearrange the others and the
  node stays under the pointer that hit it -- at the price of the reflowed part
  overlapping its neighbours, and of a wide reveal running off the edge of the
  window. The node is pinned at the point its outgoing arrow leaves, so a reveal
  grows upward, away from everything else. **Shift-click** opens a node's whole
  subtree in one go, which is neither one step nor the whole page. **unfold
  all**, **reset** and **args** lay the whole graph out afresh.

## Data model

Graph nodes: `kind` (`event` | `checks` | `group` | `def`), `label`, `deps`,
`also`, `owner`, `checks`, `never: [{ def, after }]`. Rendering is a pure
function of one mutable `expanded` set, so collapse is the same code path as
expand.

`elements()` adds the notation: `start` and `end` nodes (the dot and the bar),
`tag` (which forbidden shape this is) against `mark` (whether it wears its
number), `shown` for the abbreviated label, `neg`, and on edges `never`, `path`,
`hue` and `weak`. A check may be `{ alt: [[…], […]] }` rather than `{ p }`,
which is what the divided cell draws.

## Measured, not assumed

- `cytoscape-dagre` ignores compound nesting when ranking (puts a container
  *beside* its successor) → use `cytoscape-elk`.
- ELK needs `elk.hierarchyHandling: INCLUDE_CHILDREN`, else each box is laid out
  as its own graph and the direction does not reach inside it.
- ELK reorders siblings to minimise crossings → `considerModelOrder` **and**
  emit elements in declaration order.
- ELK is async → viewport work must happen in `layoutstop`.
- Per-node ELK options are ignored wherever the node's children are in the main
  graph, which `INCLUDE_CHILDREN` makes true of everything → a box has to ask
  for `SEPARATE_CHILDREN` before it can be laid out on its own terms.
- Inside such a box `spacing.nodeNode` is not inherited → `layered.spacing.baseValue`.
- Unconnected siblings share a layer, and a layer runs across the flow → to
  stack them, bound the layer width to one (`COFFMAN_GRAHAM` +
  `coffmanGraham.layerBound`), which still lays a chain out in order. Bounding
  the width globally would stagger alternatives too, so it is set per box.
- A box laid out on its own is sized by ELK but DRAWN by Cytoscape from its
  children outwards → `elk.padding` must cover what the style reserves, or the
  box swells past its slot and the error compounds with nesting until siblings
  overlap.
- Elements left out of a layout keep no positions at all, not their old ones →
  the forbidden shapes, which are kept out so they reserve no column among the
  real branches, need a pass of their own before being parked.
- `cy.json({elements})` PATCHES element data: a key absent from the new data
  keeps its old value → an edge that stopped carrying a `∄` went on wearing it,
  and since folding is the only thing that moves a mark, every mark was one fold
  away from being wrong. Clearing the elements and re-adding them instead costs
  a node its HTML label, the label plugin racing the rebuild — so patch, then
  remove the keys the patch left behind.
- A layout in flight that is `stop()`ped never fires `layoutstop` → anything
  deferred to it, like a local reflow's placement, is simply lost and the graph
  is left in ELK's own coordinate space. A second toggle within the ~50ms window
  did it, so toggles are queued rather than interleaved.
- A node is sized from its Cytoscape label, so that label has to have the shape
  the HTML one is DRAWN in → alternatives are columns, and measuring them as one
  run-on line gave a node as wide as every condition end to end and one line
  tall. Its `line-height` has to be the drawn one too: conditions are a smaller
  font with a margin each, which at the default leading costs about 4px a line,
  and five of them eat the padding until the border cuts the last.
- `fit` zooms a small graph enormously → clamp to zoom 1 after fitting, but do
  not set `maxZoom` (that also blocks the user zooming in).
- Anchor the viewport on the **trigger**, not the clicked node.
- A fold or unfold changes `elements()` only WITHIN what that node reveals →
  measured over 183 toggles across every claim here: no node and no edge appears
  or disappears outside it, and nothing is revealed by two parents at once. The
  exception is a forbidden shape entering or leaving the picture, which happens
  on 6 of the 8 DANE claims when the trigger is unfolded — nothing cites it
  while the stretch it governs is folded away. A local reflow cannot pin a node
  that was not there, so those fall back to laying out the whole graph.
- "Does this node draw its own edges" and "may a bounded `∄` rest here" look
  like the same question and are not → running them together moved a mark onto
  a different stretch of trace whenever an event was folded. `drawsEdges`
  answers the first, `restsAt` the second, and only the first reads the fold
  state.
- "A run through a box meets everything in it" is true of a conjunction and
  false of a box holding a CHOICE, which is met one alternative at a time →
  making every member walkable in every colour the box is touched by spread each
  alternative's `∄` colour over its siblings. On the DANE trust-base theorem
  that left two boxes of unenterable paint and a fork between three readings of
  the same run. Neither the read-back nor the snapshot could see it: both are
  insensitive to ink that changes no claim, which is why the audit exists.
- The same fact read the other way: an unbounded `∄` declared in one conjunct
  governs the steps in the conjuncts BESIDE it, since a run through the box
  meets them all. Spreading the mark only up and down from its declaration left
  those steps unmarked, so they were drawn grey inside a branch that could only
  be entered on a colour — unwalkable ink, *and* a ban left unsaid on the very
  edges it governs. The `∄` now reaches sideways through a conjunction (never
  through a choice), which is where locality said it belonged all along. The
  box-fill pass is still not redundant: it is what `reached_deployed_server_or_
  trust_base_subverted` needs, and removing it changes that diagram.
- Laying out a sub-graph on its own means handing ELK a collection whose parents
  may be outside it, which it cannot do → lay the whole graph out and throw most
  of it away. A full layout is 10-50ms on the largest claim here, so the waste
  costs nothing and the code stays short.
- An unfolded name is DISSOLVED, so each thing it holds draws an arrow of its
  own — and converging arrows mean alternatives. `chain` boxes several
  requirements together at an event for exactly this reason, but it runs before
  `placeChecks`, so a check with nowhere to ride became a leaf of the name
  afterwards and its box drew two arrows where it means one. The picture then
  offered a run per member, each missing what the others held. It went unseen
  because no name in the corpus had held a requirement AND a homeless check
  until `KeyBroken` arrived; the read-back caught it the moment one did.
- A FOLDED node's dot spoke for every alternative behind it with one stamp: its
  arrow was drawn once per absence, each copy wearing the UNION of all of them.
  So each walk appeared to forbid whatever any of them forbade — on
  `accepted_one_or_other_unoffered` that turned "no offer listed one or the
  other" into "neither", which is strictly stronger and refuses runs the theorem
  allows. `contexts` already had the per-alternative split; the dots were built
  before it existed and so could not use it. Moving `contexts` above them (a
  pure move — nothing changed) and splitting the dot's arrow per context fixed
  12 diagrams. **The read-back cannot see any of this**, since it only inspects
  the unfolded view, where the alternatives have arrows of their own and never
  meet at a dot. Caught by reading the folded picture, which is what the
  approval baseline records it for.
- A walk was named after ONE absence, so a branch under two of them drew an
  arrow per member on every step it touched. Where a smaller context shared the
  step — `{⟦3⟧}` beside `{⟦3⟧, ⟦2⟧}` — one of those copies wore the smaller
  walk's own colour while banning strictly more, and the colour stopped deciding
  which run the reader was on. 30 such pairs in 5 diagrams, which were exactly
  the read-back failures not explained by an opaque leaf. Naming a walk by its
  whole context removes all 30 and takes the read-back from 41/49 to 45/51. It
  is not the whole of the surplus-runs defect: the three DANE headlines still
  fail, and `reached_deployed_server_or_trust_base_subverted` gained runs, three
  distinguishable walks where two coloured copies used to fall together.
- The box-fill pass -- every member of a conjunction walkable in every colour
  the box is entered on -- copied onto every arrow inside the member. Where the
  member held a choice with an absence on one side, that put the entering
  colour on the dot DECLARING a ban the run is not under: on
  `peer_proof_of_possession_reachable`, a blue arrow out of the `⟦3⟧`
  declaration on a run carrying only `⟦4⟧`, and the mirror image beside it.
  `graph.js` already exempted a box holding a choice from being filled, but the
  box being filled here is the CONJUNCTION and it fills into its member's whole
  subtree. Copying onto the one branch the walk takes -- determined, as the walk
  restricted to that member's own absences -- takes the read-back from 45/52 to
  49/52 and is what made all three DANE headlines read back.
- A folded box's dot spoke only for the contexts that carry a ban. A box holding
  an alternative under NO ban -- `UnofferedOrRevoked`'s `revoked` branch -- was
  then left with no plain arrow at all, so the run entering it that way had no
  way in and the box could not be walked on the colour that run wears. The
  audit says so in as many words ("box entered on red, but this member has no
  red arrow"), and it was right: the arrow was missing, not the lint wrong. Four
  folded faults across two diagrams, now zero. **Only the FOLDED view was
  affected**, so the read-back never saw it -- caught by the audit and by
  reading the picture.

  The trap on the way: an empty context passed through the painter as a walk
  NAMED by the empty string, took a hue slot of its own, and came out as a
  coloured arrow forbidding nothing -- while pushing every real walk's colour
  along by one. An empty context is not a walk; the arrow stays plain.

theorems, 13 files); the proportions have not moved.

- **74** exec-trace (`Reachable`), 4 proof-trace (`Trace.Invariant`), 3 neither.
  Only the exec-trace ones classify runs; the rest are out of scope.
- **8** theorems have two event premises, in `HPKE_FULL` (the five

## Known gaps

All eight of DANE's standalone theorems certify, beside the theorems themselves
in `Protocols/DANE/Security/Standalone/SecurityTheorems.lean`, with clean axioms
and none of the statement opaque. All eight also *draw*, and all eight read back
as their claim — as do all twenty-two reference diagrams; the two opaque
controls are the only ones that draw `unsupported`.

- **FIXED: a whole-run `∄` that is an ALTERNATIVE inside a name was drawn on
  one step.** `seal` gave a branch with nothing in it a start dot and anchored
  its marks with `after: dot`, on the reasoning that such a branch runs "start
  of trace straight to the end, with the marks on that one edge". True at the
  top level; false inside a box, where the branch leaves the box and the run
  continues. Anchoring then did two things: it pinned the mark to that first
  step, and — since `neverMarks` skips an anchored mark outright — it took the
  absence out of the whole-run machinery, so it got no walk and no colour. The
  picture permitted the forbidden event after the merge point, which the
  theorem's branch does not. **35 marks across 17 diagrams**, including 6 of
  DANE's 8 approved baselines.

  The reading that fixed it: the `∄` is over the whole trace, so a reader
  entering that branch commits *from the start* to never introducing the shape
  — which is a WALK. Inside a box the marks now stay floating and hang on the
  dot, which has no `deps`, so `contexts` reads it as the branch that DECLARES
  a walk, and the shared arrows downstream are split per walk. **The arrows are
  split, not the name** — which is why this never was the collision with *a name
  is never split* that it looked like. `accepted_or_escaped` is the worked case:
  `⟦2⟧` is declared at the start dot inside `Escaped` and the `accepted → end`
  arrow becomes two, grey and `⟦2⟧`-coloured. **10 diagrams gained a read-back,
  none lost one, no new audit fault.**

  **The read-back went blind to this for as long as it existed, and no longer
  does.** It compares bags of atoms per run, and an unbounded `∄` is repeated on
  every edge it governs, so the copies collapsed by idempotence — before anyone
  asked how many edges the mark was actually on. A mark carried to the bar and
  one that stopped at a merge produced the identical atom. Worse, `claimCanon`
  read `absentBetween` as the same atom as a whole-run `¬`, so the scope was
  erased on *both* sides: the comparison could not have caught this however the
  picture was drawn. `scopeRun` now resolves each run's numbers against the steps
  that run took — banned on every step is `not`, banned on some is `notOn` — and
  `absentBetween` reads as `notOn`. The distinction the notation always made is
  now the distinction the check makes. `accepted_after_unrevoked_send`, whose
  absence is genuinely bounded, still matches 4 runs out of 4, so the pass
  discriminates rather than failing everything.

- **UNPINNED: two walks agreeing on every step and differing only in their
  bans.** The walk collapse keys on the step paired with the bans, so it refuses
  to merge that case — but nothing in the corpus produces it, and the control
  `accepted_one_or_other_unoffered` does not either: its two branches reach the
  shared step from start dots of their own, so their walks differ whichever key
  is used. Since walks became context-named the collapse fires **nowhere at
  all**, measured across the corpus; it is kept as a residual net for the
  property that makes a colour worth drawing, not because anything reaches it.

- **FIXED: several walks declared inside one name offered runs the theorem does
  not.** The signature: **nothing was missing** — every atom of the claim was on
  the page — but the picture had more runs than the claim, and every surplus
  atom was a `notOn`, a ban carried along part of a path.

  Two causes, found in that order. Walks were named after ONE absence, so a
  branch under two of them drew an arrow per member and a smaller context
  sharing the step wore its own colour under strictly more bans; naming a walk
  by its whole CONTEXT fixed the DNS pair. What was left was the box-fill pass:
  a conjunction makes every member walkable in every colour it is entered on,
  and it copied onto EVERY arrow inside the member rather than onto the branch
  that colour actually takes. Where the member held a choice with an absence on
  one side, the copy landed on the dot declaring a ban the run is not under.
  Which branch is determined — the one whose own context is the walk restricted
  to the absences that member declares — so the copy goes there and nowhere
  else. `accepted_with_two_named_absences` is the smallest case, four runs and
  eight arrows.

  | diagram | picture runs | claim runs | one absence per walk | before that |
  |---|---|---|---|---|
  | `reached_deployed_server_or_trust_base_subverted` | reads back | 18 | 64 | 59 |
  | `authenticated_peer_is_the_deployed_server` | reads back | 18 | 25 | 53 |
  | `peer_proof_of_possession_reachable` | reads back | 18 | 25 | 28 |
  | `answer_signing_chain` | reads back | 10 | reads back | 17 |
  | `answer_origin_authentication` | reads back | 7 | reads back | 11 |

  **Three** diagrams still do not read back, and two of them have too FEW runs
  rather than too many (`compromised_unroll` 12 against 16 — the one-absence-
  drawn-as-two defect below; `dane_client_reaches_an_attested_service_short` 5
  against 10). `endorsement_chain_soundness` has 4 against 3 and also carries an
  opaque leaf.


- **FIXED: an event with nothing above it now gets a dot.** Two shapes, one
  rule. An event with an outgoing arrow but no incoming one takes the walks its
  own arrows are on, and only the WALK's numbers, since a bounded `∄` between
  two drawn points says nothing about what came before. An event with no arrows
  at all — a member of a conjunction, which the trigger and most leaves of a
  nested one are — is on exactly the runs the enclosing box leaves under, so it
  takes the walks of the box's own arrows, climbing while the box has none
  either. `peer_proof_of_possession_reachable` went from two such events to
  nine dots; the corpus has none left.

  **Omitted where no run carries a ban.** The dot would then say only
  "something or nothing came before", which is what a missing dot already says.
  Colour alone does not earn one. So a leaf inside a forbidden shape gets none —
  its arrows are not steps a reader takes — and neither does an alternative that
  the banned run does not meet.

  Four things it must not do, all measured. Extending it to CONTAINERS puts a
  dot into a dashed box whose contents already carry the arrows — a different
  claim, and read-back 49/52 → **42/52**. The climb must stop at a CHOICE. It
  has to run AFTER the box-fill, or a walk a member carries only by way of a
  copy goes uncounted. And the climb must key on the box's own ARROWS, not on
  `contexts`: keyed on contexts it reached past the structure the arrows respect
  and put 25 runs on `dane_client_reaches_an_attested_service` where the claim
  has 10.

- **The read-back only inspects the UNFOLDED diagram.** It has to: a folded box  hides its contents, so the claim cannot be recovered from it. That is the hole
  two real defects sat in — a folded box merging alternatives under one banned  arrow, and stale marks surviving a redraw — both of which made the *folded*
  picture say more than the theorem while every check stayed green. What guards
  the folded views is the approval baseline, which records them, and a reader.

- **An alternative inside a negation is still not lifted out.** `distribute`
  does not descend into `not`, so an `∨` under a `¬` stays where it is, and the
  DNF retry fails identically. It no longer stops DANE — `¬ RegisteredDnskeyExec`
  draws, its two ways for one signed RRset to qualify becoming a divided cell on
  that RRset rather than two forbidden shapes — but a case where the choice is
  between *runs* under a `¬` would need de Morgan through `∨`, which
  `Claim.lean` does not have. There is a path in `lower.js` that would split an
  `∨` **directly** under a `¬` into one `∄` per alternative, which is the
  conjunction de Morgan asks for — but **nothing in either claims file reaches
  it**: measured at zero across all 28. Treat it as untested.
- **A `¬` nested inside another is refused, not drawn.** `denote_not_not` reaches
  the case where the two are adjacent, which is the common one. Deeper than that
  the inner negation becomes a mark of its own and hands nothing back to the
  outer, leaving a shape with nothing in it — which reads as though the absence
  were satisfied. Lowering reports `unsupported` rather than drawing it. Pinned
  by disabling `denote_not_not` and watching all three DANE claims that need it
  turn from `ok` to refused.
- **`rescope` is the one rewrite outside the certificate.** The other six run on
  the term and hand back their own lemma instance, composed with
  `Rewrites.trans`, so `isClaim` is about the shape that is drawn. `rescope`
  cannot join them, and not for want of effort:
  `conclusion_bounded_by_trigger` consumes the WHOLE theorem as a hypothesis,
  needs `tr.Reachable`, and yields an implication rather than an equivalence. To
  certify it, `isClaim` would have to say something weaker for rescoped claims —
  "the picture shows something the theorem implies" instead of "the picture is
  the theorem" — and that asymmetry costs more than the gap does. Reasoning
  about the bound by hand is simple; a certificate that means two different
  things depending on the claim is not.
- **Four `spread` instances are skipped rather than proved.** A rewrite whose
  proof does not go through is dropped and reported, so the picture shows the
  unrewritten shape — still the certified one. All four are on claims already
  too large to draw, and the whole visible cost is a size report reading 424
  nodes instead of 420.
- A claim that cannot be lowered draws the EMPTY run (just the end bar) plus the
  banner. It used to draw the exception as an event, which read as part of the
  theorem.
- An unbounded `∄` still appears on every edge it governs — that is locality, not
  a defect — but each is now a number rather than a restated name.
- Distribution duplicates whatever the branches share.
- Wide disjunctions (3–5 arms) untested; every example here is 2.
- Non-event leaves (label-flow facts like `signkeyLabel ⤳ pub`) unmodelled.
  Measured to be absent from every exec-trace statement in the corpus, so this
  is a gap for proof-trace theorems only.

- **A RECURSIVE `inductive` predicate can only be an opaque leaf.** A
  non-recursive one is now read (see below); one whose characterisation cites
  itself is refused, because the notation has no repetition form. That is
  `ChainAuthExec` (4 leaves, `answer_signing_chain`) and Attestation's
  `EndorsedPathE` and `ChainBroken` (8 leaves, across 6 of its 8 claims) --
  12 of the 14 opaque leaves left in the protocol claim files, the other 2
  being `AttackerKnows`. `accepted_reached_from_root` is the control.

  All three are LINEARLY recursive — one recursive premise, in first position —
  so each denotes a path, and a repetition form is the right target. Three
  things a back edge does not give:

  - **The loop carries state.** Each turn rebinds `zone`/`key`, and the next
    turn's premise names the key the previous one produced. "An argument name
    carries value identity along a path" is the rule that would have to gain a
    per-iteration form; a back edge under the same names asserts `zone = parent`,
    which the `descended` arm denies.
  - **A back edge is not happens-before.** Time runs down, and layout places
    events by index. A repeat FRAME around the step — drawn once, marked as
    repeatable — keeps time monotone and composes with `∄` locality, which a
    cycle edge does not: a ban on an edge traversed *n* times has no reading.
  - **Positive position only.** Every occurrence in the corpus is a conclusion,
    where "a path of one or more of these" is faithful both ways. But
    `denote_imp` draws every premise negated in one branch, and negated this
    needs "no chain of ANY length" -- a `∄` over an unbounded family, which the
    forbidden-shape notation does not have. A repetition form would have to be
    refused under `¬` the way `distribute` is, pinned by a control.

## Direction being considered

The graph was built from the theorem's **syntax tree**, but every leaf is really
a **constraint on one `tr`** — an event at an index, an event somewhere, an
absence over a region, a check on values. Syntax only decides which constraint
sets are alternatives (`∨`) and which co-occur (`∧`). That reframing explains
most of the friction hit here (absence scoping, premise-as-dependency, checks
placement) and makes multiple roots natural.

Two consequences for scope:

- The tool should require `∀ tr, tr.Reachable cfg → …` and show the error banner
  otherwise; that is what makes the picture a classification of runs.
- A premise quantified over *other* traces — `Protocols.DANE.Security.Standalone`
  `.RegisteredKeyIsTlsKey` is `∀ tr', Invariant tr' → …` — is not a constraint on
  the drawn trace at all. It should trip the banner, and the statement itself is
  probably what wants fixing.

A longer working log lives in `.untracked/theorem-visualization-findings.md`,
which is **gitignored** and therefore local-only.
